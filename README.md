# 후회 예산 기반 매수·매도 의사결정 동반자

종목을 이미 고른 초보 투자자가 한 종목의 공개 시세를 보면서 **사기 전 선택부터 보유 후 익절·손절 고민까지** 함께 검토하는 해커톤 데모입니다. 화면은 증권 서비스의 단일 종목 상세처럼 구성했지만 카카오페이증권 공식 서비스가 아니며, 어떤 주문도 전송하지 않습니다.

사용자가 더 피하고 싶은 후회와 감당 범위를 답하면 결정론적 코어가 수량·금액·분할 비중·재확인선·중단 조건을 계산합니다. 사용자가 `AI로 이유 설명받기`를 선택하면 AI는 검증된 사용자 답변과 시장 지표만 받아 장단점과 우선 검토 이유를 쉬운 한국어로 정리합니다. 종목 추천, 미래 가격·수익 예측, 적합성 판정과 실제 주문은 하지 않습니다.

## 실행

요구 환경은 Node.js 20.9 이상과 npm입니다.

```bash
npm install
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다. 첫 화면은 삼성전자 Yahoo Finance 코드 `005930.KS`를 조회하며, 상단 검색창에서 다른 Yahoo Finance 종목 코드를 입력할 수 있습니다. 현재 수직 흐름은 원화로 확인되는 국내 상장 주식을 대상으로 합니다.

AI 설명까지 확인하려면 프로젝트 루트의 `.env.local`에 서버 전용 환경변수가 설정되어 있어야 합니다.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
```

두 변수 모두 `NEXT_PUBLIC_` 접두사를 사용하지 않습니다. OpenAI Responses API 호출은 서버에서만 실행되고 `store: false`를 사용합니다. 환경변수가 없거나 AI 호출이 실패해도 합성 성공 결과로 자동 전환하지 않습니다.

## 단일 종목 화면의 수직 흐름

1. 종목명·코드, 최근 확인 가능한 가격·등락·거래량과 실제 Yahoo Finance OHLCV 차트를 확인합니다.
2. `살까 고민돼요`, `샀는데 가격이 움직여 불안해요`, `팔 시점을 고민하고 있어요` 중 현재 고민을 고릅니다.
3. 매수라면 예산, 매도라면 보유수량을 입력하고 실행기한을 빠른 선택 버튼으로 고릅니다.
4. `기다리는 동안 가격이 올라 놓치는 후회`와 `한 번에 산 뒤 가격이 내려가는 후회` 중 더 피하고 싶은 쪽, 감당 범위를 선택합니다.
5. 각 답변 뒤 동반자가 이해한 내용을 한 문장으로 되짚습니다. 이전 답변은 `수정`과 `뒤로`로 바꿀 수 있습니다.
6. 결정 코어가 일괄안·2회 분할안·3회 분할안의 수량, 금액, 장단점과 다시 확인할 조건을 계산합니다.
7. 선택한 계획의 기준 가격과 재확인 범위를 실제 차트 위에서 함께 봅니다. 이는 매수·매도 시점 예측이 아닙니다.
8. 더 피하고 싶은 후회를 바꾸면 같은 시장 snapshot과 나머지 사용자 입력을 유지한 채 비중과 우선 검토안이 즉시 다시 계산됩니다.
9. 시장가와 지정가 중 무엇을 먼저 비교할지 선택합니다. 실시간 호가가 없으므로 최적 지정가·슬리피지·체결 가능성은 계산하지 않습니다.
10. `이 계획의 반대 의견도 들어볼까요?`를 선택하면 AI가 검증된 fact ID만 인용해 반대 논거와 질문 하나를 만듭니다. 빠른 답변 뒤에는 AI가 아니라 결정 코어가 실행안을 다시 계산합니다.
11. `분할 주문 미리보기`에서 회차별 수량·예상 금액·주문 방식·중단 조건을 확인하고 모의 주문 연습을 완료합니다. 계좌나 주문 API로 전송되는 데이터는 없습니다.
12. `이 계획을 만든 근거`를 펼쳐 공개 데이터, 사용자 답변, 결정 코어 계산과 AI 설명의 책임 범위를 확인합니다.

데스크톱에서는 종목 상세 오른쪽에 동반자 패널이 붙고, 작은 화면에서는 아래에서 이어지는 시트 형태로 같은 흐름을 제공합니다.

## 공개 데이터와 차트

메인 화면은 Yahoo Finance 공개 chart endpoint의 OHLCV를 서버에서 조회합니다.

```text
https://query1.finance.yahoo.com/v8/finance/chart/{symbol}
```

서버는 응답을 Zod로 검증한 뒤 검증된 거래일만 클라이언트 차트에 전달합니다. 화면에는 다음 provenance를 보존합니다.

- Yahoo Finance 원본 URL
- 데이터 기준시각과 서버 조회시각
- 조회 구간과 간격
- 사용한 거래일 수
- 통화와 거래소 식별값
- 공개 데이터의 지연 가능성 안내

차트의 `1일`은 Yahoo Finance 분봉을 별도로 조회해 1분 데이터가 충분할 때만 사용하고, 부족하면 5분 데이터로 대체했다는 사실을 표시합니다. 두 데이터 모두 부족하면 탭을 비활성화합니다. `1주·1개월·3개월`은 검증된 일봉을 사용합니다. 분봉은 화면 표시 전용이며 결정 코어는 항상 별도로 검증한 3개월 일봉을 사용합니다. 데이터가 없는 점을 만들어 채우지 않습니다.

캔들, 거래량, 5일·20일·60일 이동평균을 표시합니다. 평균 매수가를 입력한 보유 흐름에서는 사용자 기준선을 차트에 겹쳐 봅니다. 이동평균과 거래량 설명은 서버가 검증한 일봉에서 계산한 현재 관찰만 쉬운 말로 보여주며 미래 방향을 해석하지 않습니다.

화면의 시장 요약도 원본에서 검증한 값으로만 계산합니다.

- 최근 가격과 전 거래일 대비 등락
- 20거래일 변동성
- 최근 20거래일 고저 범위
- 최근 거래량의 20거래일 평균 대비 배수

Yahoo Finance endpoint는 공식 SLA, 실시간성, 장기 지속성 또는 실제 서비스 이용조건을 보장하지 않습니다. 운영 전에는 데이터 라이선스와 이용조건을 검토하고 계약된 공급자로 교체해야 합니다.

## 데이터 원본 → 검증 → 계산 → AI 설명

```text
Yahoo Finance OHLCV ── Zod 검증 ── 최근 지표 계산 ─┐
                                                   ├─ 결정 코어 ─ 실행안·재확인선·중단 조건
사용자 답변 ──────── 입력 schema 검증 ────────────┘
                                                         ↓
                                      검증된 값만 AI가 쉬운 말로 설명
                                                         ↓
                                      모의 주문 sidecar 미리보기
```

화면의 도구 흐름은 다음 여섯 단계에 대응합니다.

1. `get_market_snapshot` — 공개 OHLCV를 가져와 출처·기준시각과 함께 검증합니다.
2. `collect_user_constraints` — 매수·매도, 예산·보유수량, 기한, 후회 우선순위와 감당 범위를 구조화합니다.
3. `build_execution_options` — 결정 코어가 일괄·2회·3회 안의 수량·금액·조건을 계산합니다.
4. `compare_regret_scenarios` — 한 입력만 바꾼 결과 차이를 실제 입력 snapshot에서 계산합니다.
5. `explain_tradeoffs` — AI가 검증된 선택지의 장단점과 우선 검토 이유를 초보자 언어로 설명합니다.
6. `prepare_demo_order` — 선택한 코어 계획을 실제 주문이 아닌 모의 주문 미리보기용 sidecar로 정리합니다.

결정 코어만 가격 기준값, 수량, 금액, 분할 비중, 우선 검토안 ID, 재확인선과 중단 조건을 소유합니다. 현재 네 개의 빠른 질문 순서는 결정론적으로 고정돼 있고, AI는 검증된 선택지의 설명을 담당합니다. AI 출력 schema에는 후속 질문 선택값을 유지하지만 완성된 입력에서는 설명 검증에만 사용합니다. AI는 새로운 숫자·시장 사실을 만들거나 코어 계산을 변경할 수 없습니다. AI 응답의 input snapshot, market as-of, 우선안 ID 또는 schema가 현재 화면과 다르면 설명을 표시하지 않습니다.

## 후회 예산

후회 예산은 수익을 예측하는 점수가 아니라, 두 종류의 불편한 결과 중 어느 쪽을 더 줄이고 싶은지 입력으로 명확히 만드는 방식입니다.

- `기다리다 놓치기`를 더 피하고 싶다면 초기 확인 비중을 상대적으로 높이는 안을 먼저 비교합니다.
- `산 뒤 내려가기`를 더 피하고 싶다면 여러 번 재확인하는 안을 먼저 비교합니다.
- 감당 범위는 목표가나 자동 손절가가 아니라, 공개 데이터가 달라졌을 때 멈추고 다시 볼 범위를 계산하는 입력입니다.

후회 우선순위를 바꿀 때 총 예산 또는 총 보유수량과 시장 snapshot은 유지합니다. 화면의 `왜 이 계획이 달라졌나요?`는 바뀐 입력과 코어 결과를 결정론적으로 비교하며, AI가 delta를 새로 쓰지 않습니다.

## 모의 주문 연동 경계

`prepare_demo_order`가 다루는 sidecar의 경계는 다음 정보까지입니다.

```ts
type DemoOrderSidecar = {
  symbol: string;
  direction: "BUY" | "SELL";
  planId: "ONE_SHOT" | "STAGED_2" | "STAGED_3";
  allocations: { sequence: number; shares: number; amountKrw: number; condition: string }[];
  totalShares: number;
  referenceTotalAmountKrw: number;
  reviewConditions: string[];
  marketAsOf: string;
  demoOnly: true;
};
```

현재 데모는 이 내용을 화면의 모의 주문 시트에만 전달합니다. 실제 서비스 연동 시에는 주문 화면이 sidecar를 받아 방향·수량을 주문 폼에 **초안으로 채우는 경계**가 될 수 있지만, 최신 호가 확인, 호가단위·수수료·세금·주문 가능 수량 재검증, 사용자 최종 확인과 증권사 주문 인증은 반드시 주문 시스템이 별도로 담당해야 합니다. 이 저장소에는 주문 API, 계좌 연결, 주문 딥링크와 모의 체결을 실제 체결처럼 보이게 하는 기능이 없습니다.

## 실패와 provenance

- Yahoo 응답 누락, schema 오류, 유효 거래일 부족, 노후화와 provider 장애를 구분하고 가격을 추정하지 않습니다.
- 시장 데이터가 실패하면 차트·수량·실행안을 만들지 않고 AI도 호출하지 않습니다.
- AI가 거절하거나 timeout·API·schema·안전 검증에 실패하면 해당 실패를 표시하며 이전 LIVE 성공이나 OFFLINE_DEMO fixture를 현재 결과로 승계하지 않습니다.
- 기존 고정 합성 fixture와 OFFLINE_DEMO 안전 계약은 회귀 기준으로 유지하지만, Phase 3.1의 단일 종목 메인 화면은 실제 Yahoo 조회를 성공 fixture로 위장하지 않습니다.
- `이 계획을 만든 근거`는 사용자 답변, Yahoo 시장 데이터, 결정 코어 계산, AI 설명을 서로 다른 구역으로 표시합니다.
- API 키, OpenAI SDK와 서버 환경변수는 클라이언트 번들에 포함하지 않습니다.
- 사용자 입력, OpenAI 요청·응답 원문과 evidence 원문을 별도 로그로 남기지 않습니다.

## 보유 후 재확인 계획과 시간축 안내

`샀는데 가격이 움직여 불안해요`와 `팔 시점을 고민하고 있어요`에서는 평균 매수가, 보유수량, 예상 보유기간, 실행기한, 감당 가능한 손실 범위와 전량·분할 선호를 입력합니다. 결정 코어는 다음 값만 계산합니다.

- 최근 공개 가격과 사용자가 입력한 평균 매수가로 계산한 현재 평가손익
- 사용자가 입력한 손실 범위를 가격·금액으로 환산한 재확인선
- 사용자가 직접 이익 기준을 입력했을 때만 그 기준의 가격·금액 환산값
- 전량·2회·3회 매도의 수량과 다음 회차 전 재확인 조건

이 값은 익절가·손절가 예측이나 정답이 아닙니다. 사용자의 감당 범위를 다시 볼 수 있는 계획으로 번역한 것입니다. 몇 주 이상 보유할 계획인데 1분·5분 차트를 보고 있으면 시간축 차이를 알리고 `일봉으로 시야 넓히기`, `원래 계획 다시 보기`, `지금 차트 계속 보기`를 제공합니다. 화면 전환을 강제하지 않으며 매매 신호로 사용하지 않습니다.

## 반대 심문 에이전트 경계

반대 심문 경로는 OpenAI Responses API의 Structured Output을 사용합니다. 모델에는 검증된 시장 fact ID, 사용자 입력, 결정 코어 결과, 데이터 기준시각·한계와 누락 정보만 전달합니다. 출력은 반대 논거 최대 세 개, 미확인 가정 하나, 허용된 질문 key 하나와 계획이 달라지는 조건으로 제한됩니다.

존재하지 않는 fact ID, 중복 근거, 새 숫자·가격·날짜, 예측·직접 매매 지시 또는 허용되지 않은 질문은 서버가 거부합니다. 사용자 답변은 고정된 빠른 선택값으로 부모 화면에 돌아오며, 모델이 계획을 수정하지 않고 결정 코어가 다시 계산합니다. 거절·미완성·timeout·연결·schema·의미 검증 실패는 결과 없는 안전 중단으로 표시하고 합성 성공으로 바꾸지 않습니다.

## 후속 확장 로드맵

다음은 현재 구현이 아니라 실제 서비스 검증 뒤 살펴볼 비즈니스 가설입니다.

- 포트폴리오 아침 브리핑
- 뉴스 기반 급등락 원인 자동수집
- 과거 거래 습관·승률 분석
- 공시·리포트 자동 통역
- 세금·양도세 계산
- 실제 조건 감시와 푸시 알림
- 실제 자동주문
- 로그인·DB·계좌 연결

## 안전 계약과 현재 한계

- 이 프로젝트는 **해커톤 데모**이며 카카오페이증권이 제공하거나 승인한 공식 서비스가 아닙니다.
- 종목 선정, 매수·매도 자체의 추천, 개인별 투자 적합성 판정, 미래 가격·수익률 예측을 제공하지 않습니다.
- 표시 수량과 금액은 최근 공개 가격을 기준으로 한 비교값입니다. 실시간 호가, 체결 가능성, 시장 충격, 수수료와 세금을 반영한 주문 제안이 아닙니다.
- 재확인선은 목표가, 손절 주문가 또는 자동 거래 조건이 아닙니다.
- 실제 주문, 계좌 연결, 로그인, DB, 알림, 다중 종목 포트폴리오는 구현하지 않았습니다.
- 운영 전에는 준법감시, 투자자문 해당 여부, 개인정보·보안, 접근성, 데이터 이용조건, 모델 평가와 장애 운영을 별도로 검토해야 합니다.

## 90초 시연 순서

1. **0–12초:** 삼성전자 상세에서 실제 Yahoo 캔들·거래량·이동평균과 `해커톤 데모 · 실제 주문 없음`을 보여줍니다.
2. **12–30초:** `살까 고민돼요`를 눌러 예산·기한·후회 우선순위·감당 범위를 답하고 일괄·분할안을 비교합니다.
3. **30–45초:** 시장가·지정가 우선순위를 고르고 실시간 호가가 없어 최적 가격을 꾸며내지 않는 경계를 짚습니다.
4. **45–60초:** `이 계획의 반대 의견도 들어볼까요?`를 눌러 fact ID 기반 반대 논거와 질문을 확인하고 빠른 답변을 선택합니다.
5. **60–72초:** 답변 뒤 결정 코어가 비중·재확인선을 다시 계산했다는 변화를 보여줍니다.
6. **72–82초:** `샀는데 가격이 움직여 불안해요`에서 평균 매수가·보유수량을 입력해 평가손익과 사용자 기준 재확인선을 보여줍니다.
7. **82–90초:** 모의 주문 시트와 근거 패널에서 `Yahoo 원본 → Zod → 결정 코어 → AI 설명 → sidecar` 경계를 마무리합니다.

매도 흐름은 같은 화면의 `팔 시점을 고민하고 있어요`에서 보유수량을 입력해 동일한 코어와 모의 주문 미리보기를 사용합니다.

## 제출 브리프 초안

### 한 줄 요약

후회 예산 기반 매매 동반자는 종목을 고른 초보 투자자가 실제 공개 차트 안에서 더 피하고 싶은 후회를 답하면, 일괄안과 분할안의 수량·조건을 검토하고 모의 주문까지 연습하게 합니다.

### 문제와 해결 방식

초보 투자자는 종목을 선택한 뒤에도 호가창 앞에서 한 번에 거래할지 나눌지 결정하기 어렵습니다. 정답 가격을 예측하는 대신, 공개 데이터를 검증하고 `기회를 놓치는 후회`와 `한 번에 거래한 뒤 가격이 움직이는 후회` 중 무엇을 줄일지 묻습니다. 결정 코어가 실행 숫자를 계산하고 AI가 이유를 친화적으로 설명하므로 방향성은 주되 계산과 설명의 책임은 분리됩니다.

### 기술과 데이터

Next.js App Router, TypeScript, Zod, Recharts와 OpenAI Responses API를 사용합니다. 시장 데이터는 Yahoo Finance 공개 chart endpoint의 OHLCV이고, 서버 검증 뒤 20거래일 지표만 계산합니다. 실제 주문 API와 계좌 데이터는 사용하지 않습니다.

### 한계·미구현

현재는 국내 원화 단일 종목의 해커톤 수직 흐름입니다. Yahoo endpoint 운영 안정성과 이용조건을 보장하지 않으며, 실시간 호가·체결 모델·수수료·세금·주문 인증, 실제 효용과 준법 적합성은 검증하지 않았습니다.
